# 0180 — Generated listend audio is deterministic and individually capped

Claim `B-0180`: at listend `b87dcac9a3c9e0059d90e698e2ec40fb2769ec41`,
startup sounds are generated locally as 8 kHz mono 16-bit WAV bytes from a seed.
Each item is capped at 40,000 samples, the fixed ping is identical on every
daemon, and generated audio is fed through the same `accept` rule as network
audio rather than bypassing it.

## Order of behavior

1. `generate(seed, kind)` chooses a short duration from the seed and calls
   `generate_n` with the derived sample count. The three kinds are silence, a
   sine tone at 180–799 Hz, and smoothed noise from a SplitMix64 stream.
2. `generate_n` clamps the requested sample count to
   `MAX_GENERATED_SAMPLES = 40,000`. `write_wav` wraps the `i16` samples in a
   RIFF/WAVE header, so an oversized request yields a bounded byte vector.
3. `sounds(seed, count)` derives a new seed per item and cycles silence, tone,
   and noise. The function itself has no total-item cap; the caller supplies
   `count`.
4. `twinkle()` has no RNG. It renders a fixed seven-note melody with a short
   per-note fade and returns one WAV byte string. Every daemon therefore
   produces the same content hash for the ping.
5. `publish_generated` skips entirely when the store is non-empty. For an empty
   store it creates `sounds(seed, count)`, appends `twinkle()`, and sends each
   byte vector through `accept_and_mirror` with `audio/wav` declared. Accepted
   hashes are reported; rejected items are reported without failing startup.

## What is durable, rejected, and left behind

Durable: accepted generated sounds are stored under their BLAKE3 hashes like
any other audio. The default provider is a seed set, not a recurring addition;
a non-empty store is left untouched. Rejected generated bytes stay out of the
store and appear in the rejection list; the declared `audio/wav` type is a
claim that the normal sniffing rule checks against the bytes.

A stable hash identifies identical generated bytes, not a live guarantee that
every daemon configured a provider or kept the bytes. Generated WAV headers are
valid enough for the closed sniff, but the generator does not decode or play
anything. No startup run or carrier test was executed.
